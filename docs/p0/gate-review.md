### Security review summary (the P0 DoD `/security-review` content)

- **Workflow:** top-level `permissions: contents: read`, with no job-level escalation. Triggers are `pull_request` plus `push: main`; there is no `pull_request_target`. There are **no `${{ }}` expressions in any `run:`** (no script-injection surface) and no secrets referenced. Every `uses:` is pinned to a full SHA and verified against its tag. gitleaks is downloaded directly (no third-party action), checksum-pinned, verified correct, and fail-closed on mismatch (tested). Install uses `--frozen-lockfile`, and pnpm 10 does not run dependency lifecycle scripts by default `[unverified — training knowledge]`. The defects are B1 (config will not load), S13 (scan scope) and N2/N3.
- **Landing page:** no XSS sink. Nothing is sent to any third party. With no endpoint it never shows a form and never submits, including with JS disabled. The 16+ notice and checkbox are present (checkbox enforced through `reportValidity()` despite `novalidate`). The defects are S4, S5, S6 and N6.
- **Health Connect reader:** least privilege holds in code (read `ExerciseSession` only; no write, background or history permission; no network egress; the output is only rendered on screen). The manifest needs an explicit, minimal permission set (S3).
- **Post-extraction `ci.yml` vs live:** `diff` shows the only differences are comments, `defaults.run.working-directory`, `cache-dependency-path`, and the gitleaks step name and comment. The jobs are equivalent ✔.
