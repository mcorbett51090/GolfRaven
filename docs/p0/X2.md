A trail counts as "confirmed" only when roster + unit + season window are all sourced from the direct fetch,
not from a research-file snippet.

**Tooling (decision 0001 Addendum G, implemented literally).** `tools/p0`'s `x2-fetch` performs the direct
fetch above and stores evidence per Addendum G's "X2 'confirmed from a direct fetch'": raw bytes, final URL,
HTTP status, `fetchedAt` (UTC), a SHA-256 of the bytes, and an extracted-text file (HTML → text with inline
elements joined as a browser copies them and whitespace collapsed; a PDF's text is derived from its stored bytes
with the pinned `unpdf@1.8.1`). `x2-verdict` re-derives the text from the raw bytes and recomputes the SHA-256 at
verdict time, so a stored text copy is never trusted. Evidence counts for a trail only when its final URL's host
equals the configured host, or differs only by a leading `www.`; any other redirect is excluded and reported. It also prints a DRAFT
candidate-name list per trail (headings/link text) — a hint for whoever writes the confirmation below, never
itself a confirmation. `x2-verdict` then implements Addendum G's confirmation rule literally against a
human-written confirmation file (quotes + evidence SHAs): a trail is confirmed only when its roster,
`completionUnit` and season window are all backed by quotes appearing verbatim (after whitespace collapsing) in
the cited evidence, and every roster name appears in it. See `tools/p0/README.md` §§3-4 for exact invocations.

### How TN, VI and RTJ evidence combine into the one manifest `x2-verdict` reads

`x2-verdict` reads exactly ONE evidence directory's `manifest.json` per run (`--evidence-dir`). Each trail's
evidence can be a mix of methods within that same manifest — `x2-fetch`/`x2-fetch --render`'s own entries and
any `x2-ingest`-merged owner-saved entries all live in `manifest.trails[trail][]` together, exactly as
`x2-ingest`'s merge-into-an-existing-manifest behavior already does (see `tools/p0/README.md` §4). Concretely,
for the final X2 verdict once TN is in:

1. `x2-fetch --render --config <VI-only config> --out-dir <one evidence dir>` — already run (the recorded VI
   captures).
2. `x2-ingest --trail TN --file <owner-saved.html> --url <stated URL> --date <stated date> --out-dir <the SAME
   evidence dir>`, once per TN page Matt saves — merges TN's `owner-saved` entries into that same
   `manifest.json`, alongside VI's `rendered` entries.
3. RTJ's evidence (Run 1's `direct` captures, already confirmed roster-only) would need its OWN prior
   `x2-fetch` run's evidence dir merged the same way if a single combined directory is wanted for one
   `x2-verdict` invocation — `x2-ingest`'s merge-into-existing-manifest behavior is generic (it doesn't care
   whether the existing manifest came from `x2-fetch` or `x2-fetch --render`), so pointing any of these tools'
   `--out-dir` at the same directory is what combines them; nothing about the merge is TN-specific.
4. One `x2-verdict --evidence-dir <that combined dir> --confirmation <one file covering TN, VI and RTJ>
   --ledger docs/p0/x2-recorded-ledger.json` then produces the single, final X2 overall verdict — TN's facts
   backed by `owner-saved` evidence (plus corroboration per the Addendum J correction), VI's by `rendered`
   evidence, RTJ's roster by `direct` evidence (with `completionUnit`/`season` left unconfirmed, per both runs
   above). **`--ledger` is REQUIRED as of the Addendum J re-gate, second round (gate finding 2c)** — the
   per-directory default was removed; the canonical ledger for TN/VI/RTJ's own captures is
   [`docs/p0/x2-recorded-ledger.json`](x2-recorded-ledger.json) (gate finding 2d), and until that file is
   committed, the run also needs `--allow-dirty-ledger` (its output will read UNOFFICIAL until then). A TN
   owner-saved fact's corroboration, if any, is either `x2-corroborate-wayback`'s own output (a real
   web.archive.org fetch, never hand-typed text — gate finding 3) or Matt's acceptance, which must ALSO be
   logged as a row in this file's own `## Log` section naming the record's `id` and `date` — `x2-verdict`
   checks this file (or `--x2-log <path>`) itself, not just the corroboration JSON.

This run did not combine them into one directory (VI's evidence and RTJ's Run 1 evidence remain in their own
separate `/tmp/golfraven-p0/...` locations) because TN — the piece that would make a combined run meaningful
