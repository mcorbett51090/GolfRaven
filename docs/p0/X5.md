# X5 — Overpass OSM coverage

## Check (verbatim, plan §10 P0)

> Overpass: OSM polygon (`leisure=golf_course`) and `golf=hole` coverage on the pilot-candidate courses.
> **Measurements recorded alongside (they set pace, not pass/fail):** US+CA `leisure=golf_course` count
> (`N_osm`); one OG render timing at ~2k facilities, warm cache; the current Cloudflare Pages file /
> `_redirects` / file-size limits (§5.2).

## Pass bar (verbatim)

> **≥ 60% of pilot-candidate courses have an OSM polygon.**

## Kill consequence (verbatim)

> < 60% ("poor", G-P0-04) → before P1, choose: manual polygons (15 min each, added to the P1 data lane) or
> Alt-5 (licensed feed).

## METHOD

Query the public Overpass API (`https://overpass-api.de/api/interpreter`).

### 1. US+CA `leisure=golf_course` count (`N_osm`) — the pace measurement, not pass/fail

```overpassql
[out:json][timeout:180];
area["ISO3166-1"="US"][admin_level=2]->.us;
area["ISO3166-1"="CA"][admin_level=2]->.ca;
(
  way["leisure"="golf_course"](area.us);
  relation["leisure"="golf_course"](area.us);
  way["leisure"="golf_course"](area.ca);
  relation["leisure"="golf_course"](area.ca);
);
out count;
```

Record the returned `total` as `N_osm`. `swc-analysis.md §10.2` cites "~15k facilities" for a comparable
directory scale `[training knowledge]` — this query gets the real OSM number, not an estimate.

### 2. `golf=hole` coverage on the pilot-candidate courses — the pass/fail measurement

This needs a bounding box (or centroid + radius) **per pilot-candidate course**, which is not yet known —
X2's direct fetch of the TN / VI / RTJ rosters supplies the course list and locations first. Once that list
exists, run one query per course (or a single query unioning all bboxes) of this shape:

```overpassql
[out:json][timeout:60];
(
  way["leisure"="golf_course"](<south>,<west>,<north>,<east>);
  relation["leisure"="golf_course"](<south>,<west>,<north>,<east>);
);
out geom;
(
  way["golf"="hole"](<south>,<west>,<north>,<east>);
  relation["golf"="hole"](<south>,<west>,<north>,<east>);
);
out count;
```

Run once per course in the pilot-candidate list (TN's 9, VI's 11–13, RTJ's 26 at 11 sites — **to be filled
from X2's confirmed roster**), using each course's approximate location (from the trail's own site, or a
first Overpass name search if the trail site doesn't give coordinates). Record, per course: whether a
`leisure=golf_course` way/relation exists at all (the "has an OSM polygon" pass criterion), and separately
whether `golf=hole` ways exist within it (a coverage-quality measurement, not itself pass/fail per this
check's bar).

### 3. Other §5.2 pace measurements (recorded alongside, not pass/fail)

- One OG-image render timing at ~2k facilities, warm cache.
- Current Cloudflare Pages file count / `_redirects` rule count / file-size limits (`developers.cloudflare.com`
  — also proxy-blocked this session, see `docs/owner/network-unblock.md`).

### Coverage calculation

`% with polygon` = (pilot-candidate courses with a `leisure=golf_course` way/relation found) / (total
pilot-candidate courses). Compute both combined and per-trail, since the kill consequence's manual-polygon
fallback is scoped "before P1" for whichever courses lack one, not necessarily the whole slate.
