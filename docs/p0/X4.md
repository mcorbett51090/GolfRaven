# X4 — GolfNow facility-page coverage

## Check (verbatim, plan §10 P0)

> GolfNow facility-page coverage of pilot courses (gap-delta C12).

## Pass bar (verbatim)

> ≥ 80%.

## Kill consequence (verbatim)

> Course-native link becomes primary for that trail.

## METHOD

**Exact URLs / pattern to fetch** (from `docs/golf-trails/research/golfnow-integration.md`):

- Deep-link pattern: `https://www.golfnow.com/tee-times/facility/<facility-id>-<slug>/search`
  (pattern directly observed live in the research session against three independent facility pages).
- Facility IDs are **not** derivable algorithmically — the research explicitly says to "manually look each
  RTJ/trail course up on golfnow.com once and hard-code the mapping." Already-observed RTJ facility IDs (a
  partial set, from the research file, not yet the full 11): `2360` Grand National, `2353` Oxmoor Valley,
  `2358` Hampton Cove, `2361` Cambrian Ridge.
- For TN (9 courses) and VI (11–13 courses), no facility IDs have been looked up yet — none are in the research
  files.

**Parsing rule:**

1. For each pilot-slate course (full rosters come from X2), search `golfnow.com` for the course name and
   record whether a live facility page exists at the `/tee-times/facility/<id>-<slug>/search` pattern (not a
   404, and not a redirect to a generic search with no results).
2. Record `facility-id`, `slug`, and `checkedAt` (date) for every hit — this is also the seed data for the
   plan's §6.1 T0 deep-link tier and the booking-host CI gate (§6.3).
3. Coverage % = (courses with a confirmed live facility page) / (total pilot-slate courses from X2's rosters).
4. Compute coverage **per trail** as well as combined, since the kill consequence ("course-native link becomes
   primary for *that trail*") is per-trail, not global.

**Tooling (decision 0001 Addendum G, implemented literally).** `tools/p0`'s `x4-verify` takes a hand-built JSON
map of slate course → `{trail, golfnowFacilityUrl | null}` (facility ids still looked up by hand on
golfnow.com, per this METHOD — the tool never searches or crawls GolfNow) and, for each non-null URL, fetches it
live or replays a saved response, applying Addendum G's "live page" definition literally: HTTP 200, the final
URL after redirects still contains `/tee-times/facility/<id>-`, and the page text contains the course name
under Addendum F's name normalisation. Coverage is computed **per trail** (`null` and non-live both count as
not covered), pass ≥ 80% per trail else kill with that trail's consequence — no combined figure decides
anything, per Addendum G. Every live response is saved for replay. See `tools/p0/README.md` §5 for the exact
invocation.

## STATUS

RUN — 2026-09-24 — **for RTJ only.** `golfnow.com` is reachable (HTTP 200, Cloudflare-fronted). X2 confirmed
0 of 3 slate trails' rosters this session (see X2.md), so TN and VI have no real course list to look up on
GolfNow — recorded below as **not run**, never guessed. RTJ's roster (11 named trail sites) was independently
verified against X2's direct-fetch evidence (quotes match verbatim in `rtjgolf.com/trail/`) even though the
RTJ *trail* overall isn't X2-confirmed (`completionUnit`/`season` missing) — it is used here because X4 only
needs course names, not those two facts.

**Important finding — GolfNow's own URL structure has changed since Addendum G's pattern was written.**
Facility ids were looked up by hand (browsing golfnow.com's own site and search results — no automation) for
10 of RTJ's 11 sites (Lakewood Club has no GolfNow tee-time facility listing found): Cambrian Ridge 2361,
Capitol Hill 2356 (Senator course), Grand National 2360, Hampton Cove 2358, Highland Oaks 2354, Magnolia Grove
2352 (Crossings course), Oxmoor Valley 2353, Ross Bridge 2362, Silver Lakes 2355, The Shoals 2357 — the first
four were already in `tools/p0/README.md`'s prior research notes; the other six found this session. Every one
of the 10 `https://www.golfnow.com/tee-times/facility/<id>-…/search` URLs returns **HTTP 200 but an
unconditional 301 redirect to `https://www.golfnow.com/courses/<other-id>-…-details`** — a different URL
shape entirely, for the correct course every time (slug and course name match). None of the 10 ever lands on
a final URL containing `/tee-times/facility/<id>-`, so Addendum H's literal "live" test — which requires
exactly that — **cannot pass for any course**, even though every one of the 10 resolves to a real, live,
correctly-named GolfNow course page. This was checked by hand against the raw HTTP response (`curl -i`, no
redirect-follow) as well as through `x4-verify` itself; both agree. **This is a genuine site-behavior change
worth the owner's attention, not a coverage gap** — see VERDICT.

## MEASURED VALUE

**RTJ: 0/11 (0.0%) vs 80% bar — mechanically KILL** per Addendum H's literal "live" test (see STATUS for why:

No course was indeterminate (`anyIndeterminate: false`) — every fetch cleanly resolved HTTP 200 to a wrong-
shaped URL, except Lakewood Club (`golfnowFacilityUrl: null`, no listing found — counts as not covered,

**TN: not run** — no confirmed roster (X2 indeterminate: blocked by the site's WAF). **VI: not run** — no

## VERDICT

**RTJ: mechanically KILL under Addendum H's literal text (0% vs 80% bar) — but flagged, not accepted at face
value.** The literal per-trail result technically triggers X4's kill consequence ("course-native link becomes
primary for RTJ"), and it is recorded as required. But the *reason* is a URL-pattern mismatch against a site
that has visibly restructured itself (`/tee-times/facility/<id>-<slug>/search` → always redirects to
`/courses/<id>-<slug>-details` now), not a lack of real GolfNow coverage — 10 of 11 RTJ sites resolved to a
correct, live, bookable-looking GolfNow course page. **Needs the owner:** decide whether to (a) update
Addendum H's "live" definition to match GolfNow's current URL shape (e.g. accept a redirect to
`/courses/<id>-…-details` as live, or drop the id-continuity requirement given the id changes across the
redirect) before re-running, or (b) accept the literal kill and let the course-native link become primary for
RTJ as written. Until that decision, this run is evidence, not a final verdict to act on mechanically.

**TN, VI: not run — no owner action needed yet; follow from X2's own unresolved status** (WAF block / SPA with
no extractable roster).
