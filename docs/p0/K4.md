> **Sync signal** = X1 **or** **K4b** (FM-05, G-P0-05). **K4b pass bar:** on ≥ 2 current Garmin golf watch
> models, a Connect IQ component records ≥ 1 fix inside a course polygon **while the user runs Garmin's native

> **Both fail** → the owner escalation fires, in writing, **before P1**: "sync with Garmin" at launch means
> file import + a one-tap watch check-in + "Open in" links, with nothing automatic; the owner signs the
> replan. **Whenever K4b fails or X1's Garmin source fails, whatever K4's overall verdict** (A2-14), the owner

> the case where X1 passes on Apple Watch + a phone app while Garmin fails. **If K4 passes on K4b alone**, the
> same written statement is sent.

## METHOD

K4 is a **combinator gate**, not an independent measurement: its verdict is `pass` if X1 passes (see
`docs/p0/X1.md`) **or** K4b passes (see the K4b protocol in `docs/owner/x1-k4b-device-protocol.md`).

1. Run X1 to its verdict (real-device Health test across 3 iOS sources + Android pass).
2. Run K4b: on ≥ 2 current Garmin golf watch models, build/install a Connect IQ component ("Trail Check-in")
   that records ≥ 1 GPS fix inside a course polygon while Garmin's own native Golf activity is running, and
   confirm the fix reaches the phone companion app **with the phone app backgrounded**, on both iOS and
   Android. Developer signup and a sample companion app are prerequisites to running this test, not the pass
   bar itself.
3. K4 = pass if either sub-check passes.
4. **Independent of K4's overall verdict:** if K4b fails, or if X1's Garmin source specifically fails (even
   while X1 passes overall on the other two sources), a written statement about exactly what the Garmin lane
   does and does not do at launch must go to the owner before P1 — this is required in both the pass and kill
   branches of K4, per A2-14.
